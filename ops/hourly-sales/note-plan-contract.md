# Source-bound note extension — existing Sales authority still applies

For call_followup with context.note_source.status=current, use canonical note-plan, NOT next-action or generic completed finish. The latter cannot certify provider effects. Other work kinds keep the existing runtime guide. No sends, no guests, no contact edits, no new prices or commitments. The source-bound disposition below is the only permitted automatic stage update.

Write a private JSON intent file, then invoke the existing configured adapter runtime with:
head_of_sales_adapter.py note-plan --id <owned-work-id> --plan-file <absolute-file>

Required fields: expected_lead_version (current context.lead_version), source_digest (exact context.note_source.source_digest), summary, facts (list), actions (list). Never include lease tokens; the adapter supplies them. Never include draft_receipt: only the canonical server can create and verify receipts.

Optional disposition={target_stage,quote} is restricted to an immutable call source with an explicit HUMAN-selected outcome: connected permits contacted only from new; not_interested permits lost with actions=[]. Text citations or model-extracted facts alone never authorize stage changes. Never infer lost/not_a_fit/contacted from free text or an ordinary note. Use the existing manual stage control for not_a_fit or ambiguous closure; keep an exact waiting question when needed. Never reopen a terminal lead or override newer human context. If the stage already matches, omit disposition.

A fact has field, value, and a verbatim quote from the exact source summary. Allowed fields: answer_kind, useful, decision_maker, interlocutor_role, repeat_reason. Existing human values prevail. Unknown is legitimate. Reception/forwarding does not prove a decision-maker conversation. A note describing two attempts remains one recorded event: summarize that distinction, do not create invented events or times. First contact is a separate dimension and all-channel coverage here is explicitly incomplete; do not certify first contact from lack of visible history. Prior dated emails/meetings/calls override a first-call self-description.

An action has stable key (lowercase letters/digits/underscore/hyphen), task_type (call/email/follow_up), title, due_at (timezone-aware ISO), quote (verbatim source), optional existing_task_id AND expected_task_version from current task context. Reconcile the existing task rather than create a duplicate. Closed, sent, cancelled or superseded tasks must not be resurrected. Refusal/pause/suppression prevails. Existing callbacks remain independent of emails. Dedupe is company/account-wide, including sibling leads and recently disposed manual tasks; same company name alone is not identity. A sibling obligation blocks a new action and requires reconciliation, not automatic reassignment/adoption through this note. due_at must be in the future, including the actual date of an adopted task; an overdue task needs explicit canonical rescheduling rather than a fabricated future date in the plan.

For an email prepare at most one draft intent: draft={recipient,subject,body_html}. The recipient must be literal and evidenced; do not strip accents, guess spelling or silently switch mailbox/thread. No active HTML/images. Use only balanced p/br/div/span/strong/b/em/i/u/ul/ol/li formatting tags with NO attributes; links, styles, comments, declarations and all resource tags are rejected. Plain text and escaped text are allowed. The server loads the existing commercial signature and validates Gmail identity, existing drafts/Sent and thread before creation; uncertainty preserves its journal and never retries create blindly. A draft is preparation, never proof of sending. Manual drafts must remain untouched. Recipient ambiguity (including REN) or provider conflict requires an honest waiting disposition, not an invented success or another draft.

For call, due_at is an authorized INTERNAL callback. Exact note dates/times must be preserved; vague scheduling can choose a business-hours internal slot, explicitly described as an internal choice, never a customer agreement. Calendar work is enqueued on the existing deterministic executor; the note receipt may remain partial until its Calendar receipt is verified. Do not call Calendar directly.

If source is superseded/unavailable, context is suppressed, a current task version is missing, or the API returns a conflict/unconfirmed provider result, stop that action. Use the existing finish command with waiting status inside its result JSON file, stating exact missing evidence/owner. Newer context must be reconciled before acting from an old note. Do not hide an unresolved requested action by submitting an empty actions list. Do not complete a model-only summary. A different next step or new work ID is not a retry. Check returned canonical receipt/readback for each supplied ID. The scheduler, not this model turn, drains subsequent batches and performs the obligation audit.
